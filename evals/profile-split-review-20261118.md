## 읽기 경로와 본문 보존

기존 `artifact-style-profiles.md`의 첫 H2 이전 서문은 선택 안내에 그대로 남깁니다. 기존 H2와 모든 하위 절은 공백과 줄바꿈까지 보존해 10개 파일로 옮깁니다. 선택 안내에는 기존 H2 제목과 링크를 남겨 이전 절 링크도 유지합니다. 서문과 새 파일의 본문을 원래 순서로 합치면 비교 기준의 모음과 바이트 단위로 일치합니다.

항상 읽는 세 문서의 범위는 유지합니다. 복합 산출물은 관련 프로필을 모두 읽으며, 독립 문서와 증거 검사는 공통 작성 파일을, 양식과 조판 및 내보내기는 조판 파일을 추가합니다. 지원서 프로필의 하위 절과 지원서 워크플로도 전문을 읽습니다. 복합 경로에서 같은 파일은 한 번만 합산합니다.

측정 도구는 이전 구조에서 필요한 절만 선택하는 경우와 파일 전문을 읽는 경우를 구분합니다. 새 구조에는 파일 단위 선택을 명시적으로 적용하며, 파일 누락을 다른 경로로 대체하지 않습니다. 경로 크기는 UTF-8 바이트 합계입니다. 토큰 수나 응답 시간, 한국어 품질의 개선율은 측정하지 않습니다.

단위는 바이트입니다. 파일 전문 읽기를 기준으로 이메일은 54.1%, UI 문구는 53.8%, GitHub 글은 53.5%, 지원서 답변 필드는 13.9% 줄었습니다. 이미 필요한 H2 절만 선택하던 환경과 비교하면 이메일, UI 및 GitHub 경로는 각각 1,222바이트 늘고 지원서 경로는 1,183바이트 늘어납니다. 선택 안내를 전문으로 읽는 비용이 추가되기 때문입니다. 필수 세 문서의 234바이트 감소는 진입 문서의 라우팅 설명을 바꾼 결과이며, 문맥과 문장부호 지침의 읽기 범위를 줄인 것이 아닙니다.

원래 프로필 모음은 35,873바이트였고, 새 선택 안내는 2,212바이트입니다. 원본 서문 756바이트와 분리한 본문 35,117바이트의 완전 일치를 확인했습니다. 위 경로는 추가 편집이나 언어 분석 참조를 포함하지 않으므로, 해당 작업에서는 필요한 참조가 더해집니다. 전체 패키지 크기 감소를 주장하지 않습니다.

## 구조와 패키지 검증

실제로 수행한 로컬 검사는 다음과 같습니다.

1. 현재 후보의 `build` 검사 267개가 통과했습니다.
2. 원본 `v0.1.0` 체크아웃을 지정한 전체 단위 테스트 130개가 통과했습니다. 읽기 경로와 본문 보존, 새 사례 형식과 원본 보존 검사를 포함합니다. 이 수량은 문장 품질 평가 횟수가 아닙니다.
3. GitHub CLI 2.97.0의 `gh skill publish --dry-run`이 통과했습니다. 실제 발행은 수행하지 않았습니다.
4. 로컬 `pre-eval`은 GitHub CLI 인증 단계에서 종료됐습니다. 전체 통과로 기록하지 않습니다. PR에 연결된 Ubuntu와 Windows 검사의 해당 커밋 결과는 별도로 확인합니다.
5. 실제 출력 기록의 입력 해시, 프롬프트, 최초 판정 형식 및 역할 분리 검사를 통과했습니다. 기존 절의 끝 빈행까지 보존한 파일에는 일반 `git diff --check`가 EOF 빈행 경고를 냅니다. 이 항목만 제외한 `git -c core.whitespace=-blank-at-eof diff --check`로 다른 공백 오류가 없음을 확인했습니다. 원본 절의 완전 일치는 별도 바이트 대조로 검사했습니다.

현재 후보의 `final`, 전체 50개 재평가와 새 설치는 수행하지 않았습니다. 과거 릴리스의 검증 결과를 이번 후보의 결과로 재사용하지 않습니다.
