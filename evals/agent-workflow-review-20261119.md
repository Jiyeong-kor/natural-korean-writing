# 역할 분리와 새 스레드 이어하기 검증

2026년 11월 19일 한국 시간 기준 기록입니다. 기준은 `main`의 `8966ff21215ddc54b9f0af018b3e24d0991f2a8f`이며 변경은 [PR #9](https://github.com/Jiyeong-kor/natural-korean-writing/pull/9)에 있습니다. 새 릴리스나 개인 설치본 갱신은 포함하지 않습니다.

이번 변경은 총괄, 작성자, 독립 검수자의 책임과 전달 자료를 구분합니다. 스킬은 위임 절차를 안내하며, 별도의 에이전트 실행기나 영구 기억 서비스를 제공하지 않습니다. 도구가 없는 환경에서 수행하지 않은 검수를 완료했다고 보고하지 않도록 명시합니다.

## 역할과 읽기 범위

모든 역할은 `SKILL.md`, 문맥 지침, 문장부호 지침을 끝까지 읽습니다. 총괄은 역할 지침과 해당 작업의 선택 안내를 추가로 읽습니다. 본문 작성과 실질 검수를 맡은 작업자는 원본 자료와 해당 역할의 참조 전체를 읽습니다. 총괄이 본문을 고치거나 내용의 타당성을 직접 판정하면 그 역할의 읽기 범위도 적용합니다.

기본 구성은 총괄, 작성자 1명, 별도 검수자 1명입니다. 사용자 지정 인원과 역할을 우선합니다. 위임받은 작성자와 검수자는 다시 팀을 만들지 않으며, 한 명의 작성자가 기준 원고를 수정합니다. 짧고 독립적인 교정에는 위임을 요구하지 않습니다. 기존 원고의 짧은 후속 수정에는 정해진 검수 조건이 유지됩니다.

지원서 워크플로는 선택 안내와 다음 다섯 단계로 나눴습니다.

| 단계 | 담당 내용과 읽는 조건 |
| --- | --- |
| 기획 | 문항 분석, 경험 선택, 직무 근거와 지원 추천을 다룹니다. 작성자와 실질 검수자가 모두 읽습니다. |
| 작성 | 경험의 선택 이유, 행위자와 대상, 문장 연결과 말투 수정을 다룹니다. 작성자와 실질 검수자가 모두 읽습니다. |
| 검수 | 같은 회사의 답변 전체, 실제 최종본과 버전 검수를 다룹니다. 작성자와 실질 검수자가 모두 읽습니다. |
| 폼 작업 | 허용된 입력, 저장과 저장본 대조를 다룹니다. 해당 작업이 있을 때 추가합니다. |
| 원본 전달 | 요청된 원본 파일과 실제 다운로드 상태를 다룹니다. 해당 작업이 있을 때 추가합니다. |

새 스레드에서는 기존의 기준 원고와 작업 기록을 읽고 최신 정정, 확정 표현, 허용 범위, 검수 버전과 남은 첫 작업을 복원합니다. 원고와 개인 기록은 재사용 스킬 밖에 둡니다. `AGENTS.md`에는 스킬과 기존 기록의 위치를 연결하는 예시만 제공합니다. 특정 앱, 모델, API 또는 문맥 크기를 필수 조건으로 두지 않습니다.

## 원문과 선행 규칙 보존

기준 지원서 워크플로의 H2 본문은 교차 참조 3곳과 최종 검수 책임을 조정한 문장 2곳만 변경해 옮겼습니다. 허용한 치환을 역적용하면 원래 순서의 본문이 바이트 단위로 복원되는지 검사합니다. 기존 H2 10개와 H3 4개의 제목 앵커도 선택 안내에 유지합니다. 지원서 프로필 본문은 기준 커밋과 같습니다.

현재 기본 브랜치에 이미 포함된 경량화와 수정 범위 규칙 외에 다음 미병합 선행 브랜치도 대조했습니다.

| 선행 자료 | 처리 |
| --- | --- |
| `rules/blind-draft-review-20261105`의 `fc2d3ffdff3388771d30de08254bdb4a6e4478e1` | 국소 수정 경계와 독자가 읽는 순서의 검토는 현재 파일에 이미 유지되어 있습니다. 공고별 블라인드 채용의 전체 준수 절차는 이번 역할 분리와 별도 범위로 남깁니다. |
| `rules/contextual-writing-20261029`의 `dc0620a54ad2be509daf4a7837cea06c333b1ca3` | 최신 정정과 실제 문항 대조, 기술별 학습 및 구현 구분, 동기와 행동의 연결, 독자에게 필요한 배경은 현재 파일에 유지되어 있습니다. 미병합 브랜치를 통째로 덮어쓰지 않았습니다. |

별도 범위인 블라인드 채용 절차에는 첫 초안 전 공식 공고와 첨부 확인, 필드별 금지와 허용 및 미확인 분류, 간접 식별 단서와 예외의 대조가 포함됩니다. 일반 공개 범위 지침이 있다는 이유로 이 전체 절차가 반영됐다고 보지 않습니다. 팀 전체 인원과 동료 수, 여러 제품의 서로 다른 사용 목적, 개인 선호의 일반화에 관한 선행 브랜치의 구체적인 예시 문구도 추가로 가져오지 않았습니다. 사실과 소유 범위, 목적, 근거 없는 일반화를 다루는 공통 원칙은 유지합니다.

## 제한된 실제 동작 관찰

[원문과 저장 결과 및 최초 최종 응답](runs/agent-workflow-observation-20261119.json)에 실제 입력과 반환 내용을 보존했습니다. 안내문을 이어 쓰는 총괄과 짧은 교정 담당은 상위 실행자가 각각 `fork_turns: none`으로 생성했습니다. 모델이나 추론 설정을 별도로 지정하지 않았으며 제공자가 확인한 실제 모델 및 실행 버전 자료는 없습니다.

### 가상 안내문 이어쓰기

초등학생과 보호자를 위한 가상 공예 체험 안내문 v4 전체와 최신 작업 기록을 제공했습니다. 사용자는 체험 순서 두 문장만 고치고, 작성자 1명과 별도 검수자 1명을 유지하며, 최종 원고를 채팅으로 받도록 했습니다. 이전 검수 R1은 v3만 검토한 상태였습니다.

상위 도구 목록에서 총괄 아래에 별도의 작성자와 검수자가 생성된 것을 확인했습니다. 작성자는 v5를 만들었고, 검수자는 그 전체를 대상으로 구체적인 대조 결과 R2를 반환했습니다. 총괄은 이전 R1을 새 원고의 완료 근거로 사용하지 않았습니다. 최종 전달문에 들어 있는 원고, 현재 기준본과 최초 v5 보관본이 바이트 단위로 같았습니다.

고친 두 문장은 다음과 같습니다.

> 먼저 준비물을 배부하고 접는 순서를 설명합니다. 그다음 참가자는 자유롭게 작품을 만든 뒤 주변을 정리합니다.

그 밖의 전체 문자열은 원문과 일치했습니다. 준비물 배부, 설명, 자유 제작, 정리 순서가 원문 사실과 일치한다는 검수자의 근거가 실제 문장과 함께 기록되어 있습니다. 원고 SHA-256은 `982823ef1cb2a278dfb6246af090aad9512ab16181f06b581f602dfc4e416afc`입니다. 작업 기록에는 원문을 보존한 채 현재 원고 전체와 버전, 담당 역할, 실제 검수 결과, 완료 상태를 추가했습니다. 저장된 내용을 다시 조회했습니다.

### 짧은 독립 교정

다른 원고 작업에 속하지 않는 가상의 한 문장을 별도 새 문맥에 제공했습니다. 원문은 “예약 명단에 대한 확인을 진행했습니다.”이며, 명사형 표현을 동사로 고친 한 문장만 요청했습니다. 최초 최종 응답은 다음과 같습니다.

> 예약 명단을 확인했습니다.

최종 응답에는 역할 계획이나 검수 완료 설명이 붙지 않았습니다. 이 결과만으로 전체 도구 호출 수나 모든 진행 안내의 부재를 인증하지 않습니다.

### 관찰의 한계

위 기록은 실제 저장 파일과 상위 실행자가 받은 최초 최종 응답을 보존합니다. 하위 위임의 요청문과 `fork_turns` 값은 총괄이 남긴 기록이며, 작성자와 검수자의 완독 및 독립 읽기 선언도 당사자의 보고입니다. 별도의 전체 도구 호출 기록을 수집한 증거로 취급하지 않습니다. 문서 이름, 해시, 읽음 선언이나 PASS만으로 모델의 실제 읽기와 이해를 인증하지 않습니다.

이는 현재 세션의 위임 도구로 수행한 두 작업의 제한된 관찰입니다. Dot에서 직접 실행하거나 개인 Codex 앱에 설치해 새 프로젝트 스레드를 연 검증이 아닙니다. 긴 대화의 실제 문맥 압축, 실행 속도, 비용, 토큰 사용량과 품질 개선율도 측정하지 않았습니다. 지원서 단계 전체의 모델 평가, 새 보충 사례 8개 전체의 판정, 기본 50개 재평가와 정식 릴리스 검증을 수행한 것으로 집계하지 않습니다.

## 자동 검사와 CI

실제로 실행한 로컬 검사는 다음과 같습니다.

1. 초기 후보의 전체 단위 테스트 147개가 통과했습니다. 독립 검토에서 발견한 두 사항을 수정한 뒤 영향받는 검사 35개도 통과했습니다. 기본 50개와 기존 공개 평가 기록을 바꾸지 않았는지 검사하는 항목이 포함됩니다.
2. 수정한 구현 후보의 `build` 검사 331개가 통과했습니다. 기록 문서를 추가한 최종 변경본의 검사 결과는 PR에서 별도로 확인합니다.
3. GitHub CLI 2.97.0의 `gh skill publish --dry-run`과 패키지 형식 검사가 통과했습니다. 실제 발행은 하지 않았습니다.
4. 로컬 `pre-eval`은 GitHub CLI의 계정 조회 인증이 없어 실패했습니다. 이를 통과로 기록하거나 검사를 제거하지 않았습니다.
5. 원문 절의 끝 빈 줄을 그대로 옮긴 네 단계 파일에서 일반 `git diff --check`가 EOF 경고를 냈습니다. 이 항목만 제외한 `git -c core.whitespace=-blank-at-eof diff --check`는 통과했습니다. 원문 보존은 별도의 바이트 대조로 검사합니다.

[초기 후보 CI](https://github.com/Jiyeong-kor/natural-korean-writing/actions/runs/44490050045)와 [검토 의견을 반영한 구현 후보 CI](https://github.com/Jiyeong-kor/natural-korean-writing/actions/runs/44490703850)는 Ubuntu와 Windows 모두 성공했습니다. 해당 작업의 `pre-eval`과 패키지 검사 단계도 각각 성공했음을 조회했습니다. 과거 `v0.1.0` 원본을 대상으로 한 CI의 `final`은 현재 후보의 릴리스 검증으로 설명하지 않습니다.

기본 평가 결과와 이전 수정본의 실제 출력은 이번 후보의 결과로 재사용하지 않았습니다. 구조, 형식, 원문 보존과 도구 검사 통과는 실제 모델의 지침 준수나 모든 환경의 호환성 보장이 아닙니다.
