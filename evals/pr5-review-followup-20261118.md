지원서에서는 특성명이 실제 행동에 맞는지, 제안과 협의 및 실행 순서를 보존했는지 확인하도록 했습니다. 수업에서 배운 내용과 독학, 개인 작업과 공동 작업의 범위도 구분합니다. 필요한 배경과 이유를 설명하되 결론 우선 요청이나 요약을 일괄 금지하지 않습니다. 상투적인 입사 적응 약속을 지워도 확인된 학습 목표와 질문에 필요한 미래 행동은 남깁니다. 미확인 회사 절차를 추가하지 않는 기준과도 함께 적용합니다.

제안서에서는 조사 여부를 모른다는 사실을 조사하지 않았거나 결과를 사용하지 않았다는 주장으로 바꾸지 않습니다. 문장만 다듬는 요청에 새 조사나 테스트 약속을 추가하지 않습니다. 복사용 본문과 작업 안내를 구분하는 기준은 도구 호출 사이의 메시지에도 적용하되 상위 지침의 필수 안내와 필요한 제한 보고는 보존합니다.

## 읽기 분량과 적용 조건

`scripts/measure_read_paths.py`는 고정된 두 커밋과 현재 파일에서 명시적 읽기 경로의 UTF-8 바이트를 계산합니다. 기본 문맥과 문장부호 지침을 줄이거나 생략하지 않습니다. 단순 작성에 추가 편집, 언어 분석, 문서 제작이나 조판이 필요한 경우는 아래 합계에 해당 참조를 더해야 합니다. 지원서 경로에는 프로필 6의 모든 하위 절과 지원서 워크플로 전문을 포함합니다.

| 명시적 작성 경로 | 최초 기준 `2419612` | 리뷰 대상 `42d1c26` | 이번 후보 |
| --- | ---: | ---: | ---: |
| 필수 세 문서만 | 48,103바이트 | 23,773바이트 | 25,425바이트 |
| 짧은 이메일 | 49,617바이트 | 59,003바이트 | 26,939바이트 |
| UI 문구 | 49,753바이트 | 59,003바이트 | 27,075바이트 |
| GitHub 글 | 49,964바이트 | 59,003바이트 | 27,286바이트 |
| 지원서 답변 필드 | 128,076바이트 | 121,999바이트 | 107,257바이트 |

절 선택이 가능한 경우 이메일 경로는 리뷰 대상보다 54.3%, 최초 기준보다 45.7% 작습니다. 공통 지침은 읽기 범위와 출력 경계 설명을 보강해 리뷰 대상보다 1,652바이트 늘었으며, 최초 기준보다는 47.1% 작습니다. 이 수치는 토큰, 응답 시간이나 문장 품질의 개선율이 아닙니다.

상위 실행 환경이 선택한 파일의 전문 읽기를 요구하면 그 지침이 우선합니다. 이 경우 이메일 경로는 최초 기준 81,967바이트, 리뷰 대상 59,003바이트, 이번 후보 61,298바이트입니다. 즉 최초 기준보다 작지만 리뷰 대상보다는 약 3.9% 늘어납니다. **절 선택 경로의 감소를 모든 환경의 실제 입력 감소로 주장하지 않습니다.** 측정 도구는 전문 읽기 경로도 별도로 출력합니다. 실제 파일 읽기 추적, 토큰과 응답 시간을 측정하지 않았습니다. 전문 읽기 환경에서도 관련 없는 프로필의 입력을 줄이려면 파일 분리가 필요합니다.

## 이번 후보의 실제 출력 점검

다음 네 사례의 최초 출력을 새 대화에서 각각 한 번 생성했습니다. 각 출력은 서로 다른 두 평가자가 판정했습니다. 생성자에게는 원문, 문맥, 요청과 스킬 위치만 전달했고, 평가자에게는 해당 사례와 실제 출력만 전달했습니다. 다른 평가자의 판정이나 작성 스킬은 전달하지 않았습니다.

| 사례 | 두 평가자의 판정 | 점검한 내용 |
| --- | --- | --- |
| `artifact-profile-short-email-001` | 모두 통과했습니다. | 없는 회신이나 기한을 만들지 않고 이메일 본문만 작성했습니다. |
| `artifact-profile-ui-dismiss-001` | 모두 통과했습니다. | 안내 닫기를 재시도나 복구 동작으로 바꾸지 않았습니다. |
| `application-trait-initiative-proposal-001` | 모두 통과했습니다. | 문제를 본 계기, 본인의 제안, 동의와 실행 순서를 유지했습니다. |
| `proposal-research-state-unknown-001` | 모두 통과했습니다. | 조사 상태를 단정하거나 새로운 조사와 테스트 약속을 추가하지 않았습니다. |

최초 출력 4개와 평가 원문 8개를 [별도 기록](runs/pr5-review-smoke-20261118.json)에 보존했습니다. 재생성과 추가 판정은 없었습니다. 기존 도구의 입력 해시는 `E39D59FEB0116E733C726C56DE1309DAC878A8EDFA3A031D6CDCD46110B17D57`이며, 보충 사례와 실제 프롬프트는 기록에 별도로 포함했습니다. 기록의 프롬프트가 기존 렌더러와 일치하고 역할 식별자 12개가 서로 다름을 확인했습니다.

이는 변경된 네 상황의 제한된 후보 점검입니다. 변경 전후의 품질 비교나 전체 50개 평가가 아닙니다. 제공자가 확인한 실제 모델과 실행 버전 자료가 없으므로 기존 Desktop 또는 Astra 프로필의 정식 결과로 인증하지 않습니다. 파일 위치를 알려 주는 전달문도 정식 생성 템플릿과 구분합니다. 부모에게 반환된 최종 메시지를 보존했으며, 전체 도구 및 안내 메시지 기록은 이 파일에 포함하지 않았습니다. 따라서 실제 참조 읽기 범위나 도구 호출 사이에 불필요한 안내가 전혀 없었다는 결론을 내리지 않습니다.

## 구조와 도구 검증

다음 검사를 실제로 수행했습니다.

1. 전체 단위 테스트 119개가 통과했습니다. 새 테스트 13개는 경로 계산과 절 경계, 사례 원본과 형식 및 보존 조건을 검사합니다. 언어 품질의 통과 횟수가 아닙니다.
2. 현재 후보의 `build` 검사를 통과했습니다. 기본 50개와 과거 자료의 해시 보존 검사도 통과했습니다.
3. GitHub CLI 2.97.0의 `gh skill publish --dry-run`이 통과했습니다. 실제 발행 명령은 실행하지 않았습니다.
4. 로컬 `pre-eval`은 GitHub CLI 인증 확인에서 종료됐습니다. 인증이 필요한 나머지 검사까지 통과한 것으로 기록하지 않습니다. PR에 연결된 GitHub 자동 검사의 해당 커밋 결과는 별도로 확인합니다.
5. `git diff --check`와 실제 출력 기록의 입력 해시, 프롬프트, 최초 판정 형식 대조를 통과했습니다.

현재 후보의 `final`, 전체 보충 사례의 실제 출력, 전체 50개 재평가와 새 설치는 수행하지 않았습니다. 과거 릴리스의 검증 결과를 이번 후보의 결과로 재사용하지 않습니다.

재현할 수 있는 로컬 명령입니다.

```sh
python -B -X utf8 scripts/measure_read_paths.py
python -B -X utf8 scripts/validate_repo.py --phase build
NKW_RELEASE_ROOT=/path/to/pinned-v0.1.0 python -B -X utf8 -W error -m unittest discover -s tests -v
gh skill publish --dry-run
git diff --check
```

원본 체크아웃과 GitHub CLI 경로는 [기여 안내](../CONTRIBUTING.md)에 따라 준비합니다. 위 구조 검사 명령만으로 실제 모델 출력이 재실행되지는 않습니다.

## 후속 작업

다음 항목의 추적 위치는 이 절입니다. 기능 구현과 실험을 시작했다는 뜻은 아니며, 새 작업이 승인되면 별도 변경과 결과로 관리합니다.

| 항목 | 이번에 분리한 이유와 다음 검증 조건 |
| --- | --- |
| 프로필 파일 분리 | 이번 P2는 리뷰가 제안한 최소 범위의 절 선택을 반영했습니다. 전문 읽기를 요구하는 환경까지 입력을 줄이려면 서문과 각 프로필을 독립 참조로 나누고 링크, 필수 파일 목록과 각 환경의 실제 읽기 기록을 다시 검사해야 합니다. |
| `final-answer-v1` 수집과 버전별 검증 | PR #3의 수집기는 특정 `read_thread` 내보내기를 전제하고 기본 모델 설정도 바꿉니다. 현재 분리된 `native-collaboration` 프로필에 그대로 복사하지 않습니다. 실제 원본 형식에 맞춘 어댑터, 실행 전에 선택한 출력 계약, 평가 동일성에 포함한 선택 로직, 누락 및 복수 최종 메시지와 턴 재사용 검사, 과거 원본 manifest 보존을 함께 설계해야 합니다. 최종 답변 검사와 전체 턴 안내 검사는 구분합니다. |
| 미사용, 현재, 후보 비교 평가 | 동일한 확인 가능 모델과 설정, 독립된 조건, 미사용 조건의 스킬 주입 방지, 익명화 및 순서 교환, 첫 출력과 실패 보존이 필요합니다. 기존 50개와 결과를 바꾸지 않고 새 표본으로 규칙 위반과 문장 품질을 나눠 평가해야 합니다. |
| 편집 보존 검사기 | 실제 수정 구간 밖의 문자, 보호 문자열, 모호한 반복 문구 위치와 미검사 상태를 처리하는 실행 도구입니다. 숫자가 같다는 이유로 의미가 보존됐다고 판정하지 않습니다. 패키지 파일 목록과 입력 해시, 실행 테스트를 함께 변경해야 하므로 이번 문장 지침 수정과 분리했습니다. |
| 개인 문체 프로필과 추가 문체 사례 | 명시한 선호와 관찰을 구분하고 근거 표본, 장르와 적용 범위를 기록해야 합니다. 개인 자료는 공개하지 않고 표본의 사실을 새 글에 가져오지 않아야 합니다. 누적 수식어와 국문 및 영문 주장 차이도 새 표본으로 중복 여부와 근거를 확인한 뒤 선택 참조에 추가합니다. 의도적 오탈자나 강제 어미 비율, 없는 경험을 만드는 규칙은 채택하지 않습니다. |

이미 있는 회사 및 문항 분석, 경험 비교와 최종 검수 규칙을 선행 버전으로 덮어쓰지 않았습니다. PR #3에서 보고된 일부 평가 진행 상황도 실제 원문과 현재 평가 동일성이 확인되지 않아 이번 결과로 승계하지 않았습니다.
