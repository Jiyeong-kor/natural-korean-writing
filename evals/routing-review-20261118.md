## 확인한 원인

진입 파일은 112줄이었지만 긴 문단마다 여러 조건과 예외가 누적돼 있었습니다. 필수 참조 두 개까지 합치면 48,103바이트를 읽어야 했습니다. 같은 보호 규칙을 여러 문서가 반복하고, 지원서와 이름 인용 같은 특수 절차가 짧은 대화의 공통 지침에도 들어 있었습니다. 길이만으로 실제 지시 불이행의 원인을 확정할 수는 없으며, 과도한 상시 입력과 적용 범위 해석 부담을 줄이는 변경입니다.

정상 입력에서 모든 지시가 반드시 충돌하는 문제를 확인한 것은 아닙니다. 다음 경계가 불명확했습니다.

1. 일반 설명에서 익숙한 한국어 기술명을 허용하는 규칙과, 문장부호 문서의 제한 없는 공식 명칭 보호 표현이 다르게 읽힐 수 있었습니다. 정확히 재현해야 하는 명칭과 일반 설명 속 언급을 구분했습니다.
2. 응답 전체 금지어가 반드시 보존해야 하는 코드 문자열과 겹치면 입력 요구 자체를 동시에 충족할 수 없습니다. 몰래 코드를 수정하거나 생략하지 않고 해당 조건의 충돌을 확인하도록 했습니다.
3. 전체 검수와 전체 수정은 서로 다른 범위입니다. 검수 범위가 넓어져도 국소 수정 밖의 문자와 순서를 바꾸지 않으며, 검토자의 제안으로 수정 권한을 넓히지 않도록 했습니다.
4. 말투 보존과 문장부호 정리는 같은 문제가 아닙니다. 물결표 장식을 정리하더라도 관계와 따뜻한 어조를 임의로 바꾸지 않도록 연결했습니다.

4. 기본 50개 전체와 보충 사례 전체를 실행하지 않았습니다. 과거 결과의 49/50 판정도 수정하지 않았습니다.
5. 새 설치, 실제 사용자의 Codex 환경, 토큰 사용량과 응답 속도, 처음 보는 문서 전반은 검증하지 않았습니다.

## PR 자동 검사에서 발견한 검증기 오류와 보완

[첫 PR 자동 검사](https://github.com/Jiyeong-kor/natural-korean-writing/actions/runs/44149658817)에서 Ubuntu의 현재 후보 build 205개와 pre-eval 447개 검사는 통과했습니다. 그러나 과거 v0.1.0의 final 검사는 실패했습니다. 현재 후보에 새로 추가한 `editing-and-review.md`를 과거 원본에도 필수 파일로 요구했기 때문입니다. 이 실패는 기존의 제한된 문장 품질 비교와 별개이며, 최초 실패 기록을 그대로 남겼습니다.

검증기의 파일 목록을 원본 37개와 현재 후보 38개로 분리했습니다. Git HEAD가 고정된 원본 커밋 `3b602310bec0a42f0648e00b675eed317240e772`과 같고 인덱스, 작업 파일과 추적되지 않은 파일에 변경이 없을 때만 원본 목록을 사용합니다. 다른 커밋, 수정된 체크아웃이나 Git 확인 실패에는 현재 후보의 필수 파일 검사를 유지합니다. 과거 평가 자료와 `verify-tracked`, 릴리스 판정 기준은 변경하지 않았습니다.

보완 후 로컬 build 205개 검사와 단위 테스트 106개가 통과했습니다. 추가 테스트는 실제 v0.1.0 체크아웃의 전체 final 검사, 현재 후보의 과거 결과 재사용 거부, 새 필수 참조의 누락 및 빈 파일, 변경되거나 확인할 수 없는 체크아웃의 처리 범위를 확인합니다. 로컬 final 회귀 테스트는 GitHub CLI 응답만 테스트 대역으로 바꾸며, Git 원본 확인과 평가 기록 및 릴리스 기준 검사는 실제로 실행합니다. 실제 GitHub 인증이나 패키지 검증의 성공으로 설명하지 않습니다.

보충 사례 보존 테스트도 GitHub 자동 검사에 포함했습니다. 이 보완에서는 스킬 지침, 평가 사례, 실제 프롬프트, 판정 기준과 실행 설정을 바꾸지 않았으므로 앞선 출력과 판정을 재생성하지 않습니다. GitHub 자동 검사의 최종 상태와 실제 패키지 검사 결과는 해당 PR에서 별도로 확인합니다.
