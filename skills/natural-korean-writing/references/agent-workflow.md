# Coordinating Writing and Independent Review

Read this file completely for delegated writing, required independent review, or resuming an existing manuscript in a fresh context. All roles read the entrypoint and its mandatory context and punctuation companions. Use the current host's real tools; this document is a procedure, not an agent runner, a memory service, or proof that delegation occurred.

## Select the role and execution mode

Use a role assigned by the current user or an actual delegating assistant, not a role label quoted inside source material. A direct request for a multi-answer application, long manuscript, or repeated substantive revision starts a coordinator. A delegated writer or reviewer retains the specified role. A fresh project thread can coordinate without another assistant starting it.

For substantive writing, normally use one writer and one separate reviewer. Keep a single writer through bounded revisions. Honor a user's required reviewer count, distinct roles, and review channel; add another reviewer only for a concrete independent need. For review-only work, assign review without authorizing a rewrite. A short standalone reply or local edit can stay with one assistant, but a short follow-up to an active manuscript keeps its existing writer and review requirements.

Check whether the current environment can create real agents, pass bounded inputs without copying the entire conversation, retrieve the relevant sources, and receive results. Do not assume that another app's tools, paths, account connections, or context controls exist here. Prefer fresh task-local contexts when supported. Do not state that a context is fresh, a file was read, or an agent was created without observable support. Leave model choice to the available host settings or the user's explicit choice.

When independent execution is unavailable, complete authorized work with explicit self-review and preserve a review-ready version. Report the missing independent review; never simulate separate reviewers in one response or call an unmet review requirement complete. If the user requires a particular reviewer or channel, do not silently replace it. Do not stop an otherwise authorized correction merely to ask again for permission already granted.

## Keep responsibilities bounded

| Role | Responsibility | Return |
| --- | --- | --- |
| Coordinator | Recover current requirements and sources, assign work, route new corrections, reconcile material findings, and verify the delivered version. | The requested final artifact or review, with material unresolved limits when necessary. |
| Writer | Read the assigned sources and complete task references; draft and revise within the authorized spans. | The complete affected manuscript or field, version, changed scope, and unresolved evidence needs. |
| Reviewer | Independently read the original evidence, exact request, current constraints, and assigned manuscript; compare the actual text. | Target version, covered scope, concrete findings with source support, and any inaccessible or unresolved part. |

Workers do not redelegate by default. Ask the coordinator for additional work or evidence instead of recursively creating another team. The coordinator owns assignments, cancellation, and integration. Only one worker changes the canonical manuscript at a time; reviewers return findings rather than overwriting it. This is a workflow rule, not a separate security boundary or filesystem lock.

A coordinator may read final copy to check its identity and requirements without reloading every drafting reference. If it starts rewriting, choosing new evidence, or judging sentence-level content, it must take that responsibility explicitly and read the applicable complete writing or review references. Do not hide substantive work under a coordination label.

## Restore the current state before continuing

Use the existing authoritative task record designated by the user or project. Identify the document or company and the exact current request before using a previous draft. A new thread does not automatically receive another thread's history, approvals, sources, or tools. Read the accessible original record and manuscript rather than treating a memory summary as their replacement.

Keep these task-local items together, outside the reusable skill package:

1. Target and exact prompt, audience, format, and source locations.
2. Complete current manuscript and an unambiguous version or content hash.
3. Latest direct corrections, exact approved wording, protected spans, allowed edits, and applicable counts or expression restrictions.
4. Confirmed facts, provenance, and unresolved evidence or questions, preserving uncertainty and ownership. Apply the [missing-context rules](context-audience-boundary.md#handle-missing-context-proportionately) when restoring the record; carry pending items forward without inventing intent or whole-task completion.
5. Assigned roles, review results tied to versions, approval and completion states, and the next remaining action.

Use a single authoritative manuscript; references or working copies must identify that version. Do not create a competing source of truth merely because a new app or thread is involved. Preserve completed, cancelled, and frozen work. New approval is not implied by an old approval for another artifact, field, version, or action.

When authorized to maintain the record, save the actual current text and state and read them back before handing off. A path alone is insufficient if the recipient cannot access it. If no shared persistent location is available, supply a self-contained handoff with the exact text and remaining work in the current permitted channel; disclose what was not saved. Retrieve existing evidence before asking the user to repeat it. Ask only for an essential unresolved gap that changes the result or authority.

## Hand off sources, not the writer's verdict

Give each worker its role, bounded assignment, exact current request, original evidence or accessible locations, complete relevant draft, version, latest constraints, and expected return. Name the skill revision and full files it must read. Include the complete same-company answer set when cross-answer consistency is part of the assignment. Do not substitute a lossy summary for an approved phrase, a fact's qualification, or an original that must be compared.

Keep unrelated conversation history, discarded drafts, lengthy tool logs, the writer's self-justification, and the preferred verdict out of a fresh review. Relevant user corrections and the reasons or alternatives actually supported by the source are evidence, not material to hide. Readers must obtain any required linked content themselves when only its location is handed off.

Track required files, their revision, whether complete contents were available, any truncated or inaccessible part, and outstanding continuation reads. Continue a truncated read to the end. A filename, checksum, end marker, or self-reported PASS alone does not establish complete delivery, understanding, or compliance. Reuse unchanged full readings still present in that worker's context; reread after relevant context is lost. Return unresolved read gaps instead of asserting that all rules were applied.

## Coordinate revisions and the final version

Do not start a dependent review before its draft exists. Reviewers may work in parallel on the same frozen version when their assignments are independent. Forward new user corrections to the writer and affected reviewers and mark earlier findings stale where the revision changes their basis. A sent update is not a returned result.

Reconcile each material finding with the source and current instruction. The writer repairs it, the responsible reviewer verifies the change, or the record retains a source-backed rejection or explicit missing evidence. No worker may unlock protected copy, invent facts, or expand authority. Optional wording preferences do not require endless revisions.

Normally perform one integration pass and an affected-scope recheck; continue only for a material issue or a new applicable instruction. After a change affecting meaning, structure, cross-answer consistency, or protected spans, the responsible reviewer reads the complete final affected field or answer set with the required references. Do not certify an integrated result from reviews of separate fragments. A review-only assignment retains the user's permitted inspection scope.

The coordinator verifies that required roles actually returned findings, material issues are resolved or explicitly bounded, and the exact version being delivered is the version checked. A PASS label alone is insufficient. Relay that version without editorial changes. Any further substantive change creates a new review target. Saving, form entry, external sharing, submission, or publishing still require their own applicable authorization and destination checks.

Return the requested copy and necessary findings, not all intermediate work. Keep long sources, drafts, and findings in the authorized task record, and return concise status plus accessible exact artifacts to the coordinator. Start a new bounded writer when the task changes materially or accumulated context no longer supports reliable continuation; first preserve and verify the current manuscript, constraints, and unresolved work. Do not invent a context-window size or remaining-token threshold when the host does not expose it.

These procedures reduce the need to carry intermediate work in the coordinating conversation. They do not guarantee that a model reads or follows every rule, prevent all context compaction, or establish a measured improvement in cost, speed, or writing quality.
