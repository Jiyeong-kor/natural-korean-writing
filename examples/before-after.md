# 한국어 교정 예시

각 예시는 문장과 함께 주어진 문맥을 바탕으로 고쳤습니다. 표현을 그대로 따라 쓰기보다, 바꾼 이유와 보존한 내용을 함께 확인해 주세요.

## 1. 일반 설명: 명사화 줄이기

문맥: 작성한 내용을 더 편리하게 확인할 수 있는 기능을 설명합니다.

고치기 전

```text
본 기능을 통해 사용자는 작성한 내용을 보다 편리하게 확인하는 것이 가능합니다.
```

고친 뒤

```text
이 기능을 사용하면 작성한 내용을 더 편리하게 확인할 수 있습니다.
```

바꾼 이유: 뜻은 유지하면서 불필요한 명사화와 번역투를 줄였습니다.

보존한 내용: 작성한 내용을 확인하는 기능과 그 편의성을 그대로 설명합니다. 새로운 기능이나 측정값을 덧붙이지 않았습니다.

## 2. 일반 설명: 실제 행동에 맞는 동사

문맥: 다른 내용을 고치면서 기획서 전체에서 서로 맞지 않는 내용도 함께 수정하라는 지시입니다.

고치기 전

```text
기획서 전체의 충돌도 함께 닫는다.
```

고친 뒤

```text
기획서 전체에서 서로 맞지 않는 내용도 함께 수정한다.
```

바꾼 이유: 서로 맞지 않는 내용을 고치는 행동이므로 `닫다` 대신 `수정하다`를 썼습니다. 영어 `close`를 언제나 같은 동사로 옮기지 않습니다.

보존한 내용: 기획서 전체를 대상으로 하며, 다른 수정과 함께 처리해야 한다는 지시를 유지했습니다.

## 3. 기술 설명: 서술어에 맞는 조사

문맥: 프로그램이 설정 파일에 접근해 설정값을 읽습니다.

고치기 전

```text
프로그램은 설정 파일을 접근해 설정값을 읽습니다.
```

고친 뒤

```text
프로그램은 설정 파일에 접근해 설정값을 읽습니다.
```

바꾼 이유: `접근하다`의 대상인 설정 파일에 조사 `에`를 붙였습니다.

보존한 내용: 프로그램이 설정 파일에서 값을 읽는 동작을 유지했습니다. 파일을 수정한다고 쓰지 않았습니다.

## 4. 기술 설명: 행동의 주체 구분

문맥: 서버가 응답을 보내고, 클라이언트는 응답을 받으면 화면을 갱신합니다.

고치기 전

```text
서버의 응답이 클라이언트에 전송되어 화면을 갱신합니다.
```

고친 뒤

```text
서버가 응답을 보내면 클라이언트가 응답을 받아 화면을 갱신합니다.
```

바꾼 이유: 응답을 보내는 주체와 화면을 갱신하는 주체를 나눠 썼습니다. 응답 자체가 화면을 갱신하는 것처럼 읽히지 않게 했습니다.

보존한 내용: 서버의 전송, 클라이언트의 수신, 응답을 받은 뒤 화면을 갱신하는 순서를 유지했습니다.

## 5. GitHub PR: 완료한 작업

문맥: 문서의 오타를 수정했습니다. 다른 변경이나 테스트 결과는 주어지지 않았습니다.

고치기 전

```text
문서의 오타 수정에 대한 작업을 진행했습니다.
```

고친 뒤

```text
문서의 오타를 수정했습니다.
```

바꾼 이유: 실제로 고친 대상과 행동을 바로 썼습니다.

보존한 내용: 문서의 오타를 고쳤다는 사실을 유지했습니다. 테스트 결과나 다른 개선 사항을 만들지 않았습니다.

## 6. GitHub 리뷰: 구체적인 수정 요청

문맥: 첨부 파일이 없어도 제출할 수 있어 빈 문서가 등록됩니다. 첨부 파일이 있을 때만 제출할 수 있도록 수정을 요청합니다.

고치기 전

```text
이 부분은 문제가 있는 것 같습니다. 확인 부탁드립니다.
```

고친 뒤

```text
첨부 파일이 없어도 제출할 수 있어 빈 문서가 등록됩니다. 첨부 파일이 있을 때만 제출할 수 있도록 수정해 주세요.
```

바꾼 이유: 문맥에서 확인된 문제의 발생 조건과 결과를 밝혔습니다. 무엇을 고쳐야 하는지도 구체적으로 요청했습니다.

보존한 내용: 빈 문서가 등록되는 문제와 제출 조건을 바꿔 달라는 요청을 유지했습니다. 이미 수정한 것처럼 쓰지 않았습니다.

## 7. UI 버튼: 행동을 짧게 표시

문맥: 작성 중인 문서를 저장하는 버튼입니다.

고치기 전

```text
사용자의 작업 흐름 개선을 위해 작성 중인 문서를 저장하는 버튼입니다.
```

고친 뒤

```text
저장
```

바꾼 이유: 버튼에는 누르면 실행되는 행동을 표시했습니다. 사용자가 버튼을 선택하는 데 필요하지 않은 제작 의도는 뺐습니다.

보존한 내용: 문서를 저장하는 행동을 유지했습니다. 저장할 문서는 편집 화면의 문맥으로 알 수 있습니다.

## 8. UI 안내: 저장 실패와 재시도

문맥: 인터넷 연결이 끊겨 저장에 실패했습니다. 연결을 확인한 뒤 다시 시도할 수 있습니다. 저장하지 못한 내용이 남아 있는지는 확인되지 않았습니다.

고치기 전

```text
인터넷 연결이 끊어진 관계로 저장 작업을 수행할 수 없습니다. 연결 상태에 대한 확인 후 저장 작업을 다시 진행해 주시기 바랍니다.
```

고친 뒤

```text
인터넷 연결이 끊겨 저장하지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.
```

바꾼 이유: 확인된 실패 원인과 결과를 먼저 알리고, 사용자가 할 수 있는 행동을 안내했습니다.

보존한 내용: 저장에 실패했다는 사실과 재시도 방법을 유지했습니다. 작성한 내용의 보존 여부나 재시도의 성공을 약속하지 않았습니다.

## 9. 외부 이메일: 답변이 없는 상태에서 다시 연락

문맥: 지난 월요일에 자료를 보냈으나 아직 답변을 받지 못했습니다. 상대방이 자료를 확인했는지 묻습니다.

고치기 전

```text
답장드립니다. 지난 월요일에 보내드린 자료의 확인 여부에 대한 회신 부탁드립니다.
```

고친 뒤

```text
지난 월요일에 보내드린 자료를 확인하셨는지 알려 주세요.
```

바꾼 이유: 아직 답변을 받지 않았으므로 답장이라는 표현을 뺐습니다. 상대방에게 어떤 답을 원하는지 직접 물었습니다.

보존한 내용: 자료를 보낸 시점과 확인 여부를 묻는 요청을 유지했습니다. 새로운 기한을 정하거나 상대방이 자료를 읽었다고 단정하지 않았습니다.

## 10. 포트폴리오: 담당한 구현 내용

문맥: 작성자가 누구인지 이미 알 수 있는 포트폴리오입니다. 작성자는 파일 업로드 기능과 오류 안내를 구현했습니다.

고치기 전

```text
저는 파일 업로드 기능을 구현했습니다. 이 구현을 통해 오류 안내를 제공했습니다.
```

고친 뒤

```text
파일 업로드 기능과 오류 안내를 구현했습니다.
```

바꾼 이유: 이미 알려진 작성자를 반복하지 않고, 구현한 두 대상을 한 문장으로 정리했습니다.

보존한 내용: 작성자가 파일 업로드 기능과 오류 안내를 구현했다는 사실을 유지했습니다. 이용 실적, 성능, 팀 기여도를 덧붙이지 않았습니다.

## 11. 학습 자료: 먼저 알아야 할 개념

문맥: 비트와 바이트의 관계를 처음 배우는 독자에게 설명합니다. 비트는 0 또는 1을 나타내고, 1바이트는 8비트로 이루어집니다.

고치기 전

```text
바이트는 8비트로 이루어집니다. 비트는 0 또는 1을 나타냅니다.
```

고친 뒤

```text
비트는 0 또는 1을 나타냅니다. 비트 8개가 모이면 1바이트가 됩니다.
```

바꾼 이유: 바이트를 설명하는 데 필요한 비트를 먼저 소개했습니다.

보존한 내용: 비트가 나타내는 값과 비트 8개가 1바이트를 이룬다는 관계를 유지했습니다. 새로운 계산이나 연습 문제를 추가하지 않았습니다.

## 12. 대화: 높임 수준 맞추기

문맥: 상대방이 제안한 문장이 앞서 쓴 문장보다 자연스럽다고 존댓말로 답합니다. 평가 이유는 주어지지 않았습니다.

고치기 전

```text
네 문장이 낫습니다.
```

고친 뒤

```text
제안해 주신 문장이 더 자연스럽습니다.
```

바꾼 이유: 상대방을 가리키는 표현과 문장 끝의 높임 수준을 맞췄습니다.

보존한 내용: 제안한 문장이 더 자연스럽다는 비교와 존댓말을 유지했습니다. 근거가 없는 칭찬이나 평가 이유를 덧붙이지 않았습니다.

## 13. 지원서: 실제로 확인한 내용을 쓰기

문맥: 다음은 가상의 서류 접수 화면을 점검한 기록입니다. 작성자는 필수 항목을 비우고 제출 버튼이 활성화되는지 직접 확인했습니다. 화면 전체의 품질이나 자동화 테스트 결과는 확인하지 않았습니다.

고치기 전

```text
입력 기능의 동작을 검증했습니다.
```

고친 뒤

```text
필수 항목을 비운 상태에서 제출 버튼이 비활성화되는지 확인했습니다.
```

바꾼 이유: 무엇을 어떤 조건에서 확인했는지 밝혔습니다. `검증했습니다`를 다른 단어로 기계적으로 바꾼 것이 아니라 독자가 실제 점검 내용을 알 수 있도록 했습니다.

보존한 내용: 버튼 상태를 확인한 사실만 남겼습니다. 버튼이 실제로 비활성화됐다는 결과, 자동화 테스트나 서비스 전체의 품질까지 확인했다고 쓰지 않았습니다.

문장 구조를 더 살펴보려면 [한국어 문장 작성 원칙](../skills/natural-korean-writing/references/korean-language-principles.md)을 참고하세요. 글의 종류에 따른 기준은 [문서별 작성 기준](../skills/natural-korean-writing/references/artifact-style-profiles.md)에 정리되어 있습니다.

자신의 문장에도 적용하려면 [설치 방법](../README.md#설치)과 [복사해서 실행할 수 있는 사용 예시](../README.md#사용법)를 확인해 주세요.
